# 本轮开发机直连基线

此项是配置实际项目前完成的公共服务入口网络基线，**不是已接通本应用的 Supabase 项目**。该基线没有使用实际项目 URL、公开 key 或账号；后续真实项目进度以 README 为准。

## 如何保证不走本机代理
- curl 禁用个人配置（`-q`），移除大小写 HTTP/HTTPS/ALL_PROXY 环境变量，并设置 `--noproxy '*'`。
- 强制 IPv4 且绑定物理网卡 `enp0s31f6`，本机源地址 `10.21.1.227`。
- 对实际远端 IP 读回路由，均经 `10.21.1.1`、物理网卡出站，没有选到本机 `singtun0` 路由。
- 没有停用或修改全局代理、路由、防火墙及其它业务服务。无法由这项测试证明上游路由器内部的配置。

## 实测结果
- Supabase 官网 HEAD 连续 3 次 HTTP 200，TLS 校验通过。
- 管理 API `/v1/projects` 连续 3 次返回 HTTP 401，TLS 校验通过。请求故意未带访问令牌；证明网络入口可达，不代表已获得账号或数据库访问权限。
- 首次官网完整 GET 虽收到 HTTP 200 和有效 TLS，但 12 秒内仅收到部分内容，触发超时；不能据此承诺整页下载或项目接口长期稳定。

机器原始结果位于项目外验收目录 `supabase-direct-connectivity.json`，含实际源/远端地址、DNS/TCP/TLS/首字节与总耗时、退出码及路由。

## 下一步
拿到用户实际项目 URL 与 publishable/anon key 后，再测该项目 Auth/REST 入口。真实登录、本人数据 CRUD、RLS、跨设备及手机网络仍须单独验收。不要把官网或管理 API 连通误报成真实项目同步已经成功；不要在聊天或 VITE 配置中提供 service_role、数据库密码或个人 access token。
