# 原型观察与设计约束

来源：用户提供 Figma Prototype（肠记 · 肠道日常记录 / Mobile Web，文件键 3rw2cbzv9ri4bZzz5m8SuX，起始节点 19:2962）。只观察公开原型，没有编辑 Figma。

## 已实际浏览的页面
截图清单见 `prototype/manifest.json`：首页、历史、统计、设置、计时中、如厕表单、餐次提醒、饮食表单。

## 视觉方向
- 暖白背景与卡片、蓝色主操作、细边框、少量圆角、低饱和警示色；避免渐变大屏后台风格。
- 页标题为中文衬线风格，正文系统无衬线字体；不依赖国内访问不确定的字体 CDN。
- 四页底部固定导航，页面内容有足够下边距；表单主按钮清晰可触摸。
- Figma 中的假手机状态栏不是产品功能，网页不绘制假状态栏或固定示例日期。

## 会影响数据结构的细节
- 一次如厕可以先硬后稀，形态为有顺序的列表，不是单选字段。
- “没有排出”“不确定”“没看清”“未记录不适”必须独立于明确没有不适。
- 补记的实际发生时间与记录时间分开，估计时间/耗时保留标记。
- 三餐提醒状态与餐次实际记录分开；没有回应不等于没吃；确认没吃后不再提醒该餐次。
- 常用组合只是填充，不能点击后自动新建真实记录。
- 统计展示未知/缺失，不把未知变成0或医学结论。
- 导出包含原始时间、估计标记及缺失信息。

## 首版限制必须在应用中诚实说明
没有 Supabase 项目配置时是本机记录模式；云账户、网络、迁移和跨设备需真实项目再验收。照片上传和关闭网页后的后台推送不在首版，不把通知授权按钮当成完整后台提醒服务。示例数据只允许显式标记的演示模式或测试夹具，不冒充用户真实记录。
