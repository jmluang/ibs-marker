# 首版架构与验收契约

## 交付层级与前提
- **本地交付**：可以独立运行/构建、保存三类真实记录、刷新恢复、编辑删除、检索统计与导出；浏览器自动化覆盖 Chromium 320/390/桌面。没有伪造样例默认混进真实记录。
- **云端代码交付**：SDK、数据库迁移、权限、同步及设置组件可编译并通过隔离测试；尚无实际 Supabase 项目，不能宣称真实 Auth/跨设备同步/亚洲区域网络已验收。
- **云端上线验收阻塞项**：项目创建、选择亚洲区域、实际迁移、固定账号创建、真实网络与设备验证。不开通付费、不申请资源、不在未知环境执行迁移。
- **不在本轮**：照片、AI/医疗结论、网页关闭后云推送、真实 iPhone/PWA 安装验收、应用锁或本地数据库加密。离线缓存/账号分区不是共享设备隐私锁；导出含健康数据，提供提示，默认不接第三方分析/远程日志。

## 身份和可见状态
- 命名空间明确为 `local` 或 `user:<auth UUID>`。云配置存在时默认要求登录；进入本机模式必须由用户明确选择。
- 每次激活、退出、会话失效、切号都增加内存 identity generation：立即清空当前可见记录、草稿、活动计时与提醒状态，再异步载入目标分区。异步初始化/同步回包仅在 namespace 与 generation 都匹配时应用。
- 注销/失效终止该代的同步和前台提醒。认证失败与网络离线分开显示；不静默降级到本机。
- 本机匿名数据不自动并入云账号；首版不提供隐式迁移。后续导入必须明确确认，采用可恢复的流程。
- 登出保留该账号的 IndexedDB 副本，但在账号未登录时不载入或展示；重新登录同号才恢复。设置可清除本机副本，先警告未同步数量并建议导出，取消不得丢数据。

## 领域判定
- 统一事件包含稳定 UUID、kind、occurredAt（实际发生时间）、createdAt、updatedAt、估计时间标记与删除墓碑。界面日期以 Asia/Shanghai 为准，排序只按 occurredAt，不能用创建时间替换补记时间。
- 如厕结果是 passed/none/unsure；none/unsure 的便形数组必须为空，passed 至少一项（1–7 型或 unknown）。多形态数组保留顺序。
- 不适是 reported/none/unknown；reported 至少一个症状，程度允许显式未知；none/unknown 不附冲突症状。验证拒绝矛盾输入，不在后台悄悄改用户选择。
- 耗时来源区分实际计时、估计、未知；未知不填0，结束不得早于开始。最后一次排便只统计 passed。
- 正餐按上海日期与 breakfast/lunch/dinner 归属，每个餐次的当前记录可编辑，零到一条；加餐可多条。明确没吃后又进食，用户通过编辑该餐次改变状态，不能同时留下互相矛盾的当前状态。提醒是偏好，不代替发生时间。
- 正餐是否已确认由有效的 eaten/skipped 决定；未响应保持未记录。补记到当天对应餐次后停止提醒；关闭提醒不改变历史记录。稍后提醒按上海日期/餐次单独保存到期时间。
- 如厕次数包括全部如厕，排便次数仅 passed；便形分布按已知便形片段计数，unknown 单列，不将 none/unsure 算便形；不适比例分母只取 reported+none，unknown 单列；平均耗时只计已知合法耗时。
- 完整度不输出含糊的总分：展示正餐确认数/当日启用餐次数、事件必填确认数/应确认数，并列明缺项。空数据展示未记录，不据此推断身体状况；正常/异常不作医学诊断。

## 本地事务与多标签
- 记录写入/修改/墓碑与对应 outbox 写入在同一个 IndexedDB 事务；事务成功前不显示保存成功，失败保持用户表单/原记录可恢复。
- 计时中保存 startedAt。结束按钮先持久化 endedAt 与编辑草稿；最终保存时同事务生成稳定同ID记录、加入 outbox、清除活动状态。并发结束/双击以该稳定 ID 幂等。
- 一个 namespace 只允许一个活动计时；同事务检查，另一标签看到现有计时而非再新建。标签页使用 BroadcastChannel 通知载入最新状态；基于旧 revision 的编辑拒绝并提示，不静默覆盖。
- 每次修改有新的 changeId；在途请求返回仅确认对应 changeId，不能清掉后来编辑。ACK 与远端落地/游标推进也使用事务。
- IDB 升级阻塞、写满和事务中断必须显示可重试错误，不自动清空数据库；PWA 更新不删除 IDB/未同步队列。单元测试使用故障注入；浏览器覆盖刷新恢复和两标签页。

## 云同步协议（代码/隔离验证，不冒充已接真实项目）
- 统一 outbox 操作包含资源类型、资源 ID、changeId、baseVersion、快照/墓碑；设置也作为有版本的独立资源。
- 服务端提供单一受鉴权 RPC，原子执行当前 auth.uid() 所有权/baseVersion 校验、写入、version递增、变更日志以及 changeId 结果账本。相同 changeId 重试返回原结果；同ID不同内容拒绝。禁止前端通过普通表更新绕过版本/账本。
- 每用户写操作使用数据库事务/锁串行处理竞争。RPC 若需 SECURITY DEFINER，限定 search_path、拒绝未登录、从 auth.uid() 而非请求 owner取身份，并对每次查询显式限定 owner。仅 authenticated 可执行，禁止 anon/PUBLIC；客户端表写入权限撤销。
- 只读接口受 RLS 限制，且 SQL 测试必须 SET ROLE authenticated/anon，不可用数据库管理员绕过RLS后声称隔离通过。覆盖匿名、跨用户select/insert/update/delete、伪造owner及RPC的跨用户访问。
- 服务端使用单调递增 change-log 序号作游标，按序分页，从0开始首次全量。每批远端记录落地和游标推进同本地事务，重放幂等。首版不清理变更日志/墓碑；旧设备回归先拉取，再发送原baseVersion，不能复活已删除记录。
- 冲突是显式对象，保存本地和远端版本，不清队列、不自动覆盖。记录允许选用远端，或明确复制本地为新记录；设置允许选远端或以当前远端版本重试本地设置，再冲突则继续提示。保留本地复制可能与正餐唯一约束冲突时，要先由用户改为加餐或选择版本，不悄悄丢字段。
- 云账号与本机互不混合。CloudPanel公开接口由A阶段确认，父负责最终接入设置页。未配置时不调用API；配置错误不冒充本地保存成功；未联网的云写先进入该账号outbox并明确“待同步”。

## 必测清单
1. 领域：未知/否定、合法便形组合、跨日时间、正餐编辑、统计分母、完整度与导出。
2. 本地：持久化失败、事务取消/升级阻塞、同事务 outbox、计时恢复/结束幂等、多标签旧编辑与单计时。
3. 身份：A→B后的迟到回包、退出后不展示旧记录/草稿/计时、匿名数据不自动迁移、未同步副本清除确认。
4. 同步：服务端已提交响应丢失后的重试、在途再次编辑、删除冲突、同时间/分页边界、墓碑旧设备回归、settings冲突。
5. 迁移权限：隔离 PostgreSQL实际执行SQL和RLS/受控RPC；测试夹具auth.uid函数明确不是供应商Auth真验收。
6. 浏览器：三类记录新建/编辑/删除、草稿和计时刷新、多标签、历史/统计、食物模板、下载导出、320/390/桌面截图及无横向溢出。
7. 最终类型检查、单元测试、构建、需求审查→质量/安全审查→集成验证。实际 Supabase、iPhone安装与后台推送不满足前提时保持单列待办，不勾成完成。
