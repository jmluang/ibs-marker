# 私有用户名密码登录

## 目标与边界
- 只保留预置私有账号的用户名/密码登录，不提供公开注册、访客或云配置下的“仅本机免登录”入口；取消用户邮箱/验证码步骤，不取消真正的认证、JWT 校验、会话失效及 RLS。
- 继续使用 Supabase Auth 管理密码和会话。用户名通过固定、可重复的内部标识映射登录；内部邮箱不展示、不发送邮件。账号由受控服务端创建并预确认，不能以浏览器自动确认或用户 metadata 绕过。
- 公开注册与匿名登录必须在 Supabase Auth 服务配置中真正关闭，并读回 `disable_signup=true`、匿名登录关闭；只隐藏按钮不算完成。配置读回后，用公开 key 对受控合成标识验证直接注册与匿名登录均被服务端拒绝（必须为禁用错误，不把邮箱格式错误或 SMTP 失败当通过）。若意外创建测试账号，仅清理这次创建且能证明归属的测试账号，中止交付。数据库密码不等于 Auth 管理权限，不通过直接写 auth.users 或数据库触发器冒充管理 API。
- 缺授权或空应用密码须在任何云写入前退出；中途失败不得自动重开注册。
- 密码、管理令牌只留本机私有 .env，不使用 VITE_；保留原数据库密码和已有值，不覆盖用户编辑。默认用户名 admin，应用密码由用户填写；不复用数据库密码。

## 关键步骤
1. 确认可用的管理权限。当前仅有数据库密码，缺少管理 API 授权；在同一 .env 预留 APP_USERNAME、APP_PASSWORD、SUPABASE_ACCESS_TOKEN。建议只授权本项目、短有效期，包含 Auth 配置写入及项目 API 密钥读取。
2. 冻结用户名映射与验证规则：原样、大小写敏感，不做静默改名；支持 UTF-8、禁止空白边缘和控制字符，UTF-8 不超过 30 字节；固定映射为 `u-<UTF8 原始字节的 lowercase hex>@ibs-marker.invalid`。前后端共用纯函数。Admin 创建显式 `email_confirm:true`，读回确认状态并进行真实密码登录；不预设 .invalid 必定被供应商接受，拒绝即中止部署，不静默换域名或映射。
3. 修改登录 UI 和控制器：用户名代替邮箱，不出现邮箱验证、注册或密码找回入口；展示真实用户名而非内部邮件标识。私有模式下拒绝 enterLocal、隐藏免登录入口，缺配置不得静默进入本机；保留旧本机分区但不自动导入或删除。
4. 实现有界、可测试的服务端初始化工具：先关闭公开注册与匿名登录并读回，再用受控 Auth Admin API 创建且预确认一个私有账号；不覆盖其它账号。使用本机受保护的初始化归属凭据与受控 app_metadata 核验 UUID；只有证明由此次初始化管理的既有 UUID 才可更新密码，重复运行不增重复账号。仅 email 匹配、来源不明或归属凭据缺失时中止，不自动接管。管理 API 获取的服务端 key 只在进程内使用，不记录。无授权或密码为空时 fail closed，不改变云状态；部分失败也不自动恢复公开注册。
5. 需求/质量复核通过后，完成真实服务配置和账号初始化；核对匿名拒绝、正常用户登录、错误密码拒绝、无验证步骤，并验证网页只包含公开 key。既有会话/退出/多标签/离线状态与域数据回归。
6. 只有服务端注册开关读回为关闭、预置账号确认成功、真实登录通过后，才替换当前 5217 预览构建。保留现有精确 LAN 监听与 ACL，不 commit/push/公网发布。

## 验收
- 页面只需用户名/密码，无公开注册或免登录入口；访问历史/统计等 hash 也不能绕过。
- 正确账号可获真实 Supabase 会话且可访问本人分区；错误密码不能；退出后无旧数据。
- Auth 的 `disable_signup=true`、匿名登录已关闭；公开 key 的直接注册与匿名登录实测被禁用错误拒绝；私有账号已确认且真实密码登录成功，没有邮件发送或真人邮箱依赖。
- 启动恢复会话、退出、多标签和离线缓存均不能恢复访客/本机免登录，也不能展示前一身份数据；旧本机分区保留但不自动合并。
- `.env` 经 Git 忽略且权限 `0600`；密码/管理 key 不得经 Vite 配置、构建替换或公开资产间接进入 bundle、URL、日志或聊天；脚本不输出 token/密码；所有外部写入均精确读回。
- 保留所有旧数据、RLS 和同步事务语义；用例、构建和现有 LAN 来源约束通过。
