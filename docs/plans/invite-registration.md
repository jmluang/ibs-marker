# 邀请注册与 15001 / Cloudflare 域名

本计划替代 private-username-auth.md 中“只预置账号、不开放应用内注册”的部分；不执行旧的预置账号流程。

## 已核实与授权
- 用户要求用户名/密码，无邮箱验证；注册必须输入固定邀请码，预期值只放服务器私有 .env，前端不得包含或提示。邀请码字段唯一可见提示为“输入邀请码”，无示例、说明或码值。
- 应用服务端口改为 15001，用户已授权通过自有 Cloudflare Tunnel 域名公开访问。原 5217 服务保持，未经确认不提交/推送、不改其它服务。
- 实测域名 HTTPS 证书通过，当前 502。cloudflared 在 Docker bridge，目标已正确指向 http://10.21.1.227:15001；该端口未监听。不必修改隧道或重启容器。
- 真实 Supabase 表、RLS 与 RPC 权限只读核对通过。Auth 当前无账号，原生公开注册开启；本机缺管理 PAT/服务端 API key，不能只隐藏入口便声称邀请码不可绕过。

## 实施
1. 共享原样用户名映射 `u-<UTF8字节hex>@ibs-marker.invalid`，上限 30 字节、拒绝控制字符和边缘空白，不改密码；使用真正 Supabase Auth/JWT/RLS。内部邮箱不展示、不发邮件；Admin 创建 email_confirm:true 并读回确认状态，供应商拒绝内部域时停止，不静默换规则。
2. Node 服务端精确监听 10.21.1.227:15001，提供静态构建和 POST /api/register。只在服务端读取邀请码，固定长度摘要后 timingSafeEqual；错误邀请码不能调用 Admin API。严格 JSON 字段/大小/超时、同源约束、IP/全局限流、重复用户名不得重置已有账号。只信任明确的本机/Cloudflare 容器源代理头，不信任任意 XFF。
3. 注册通过后调用服务端 Auth Admin API 创建已确认账号，再由前端正常密码登录。服务端密钥从不进浏览器；请求体、密码、邀请码及 provider token 不落日志。出站使用现有 curl 的配置 stdin（不把秘密放进 argv），禁用代理并绑定物理接口，不执行 shell 字符串，不跟随携带凭据的任意重定向。
4. 受控配置工具用用户私填的管理授权关闭 Supabase 原生公开注册及匿名登录，读回两个开关；必要时读取本项目现有服务端 key 到私有 .env。无授权先 fail closed，不改其它 Auth 设置，不创建预置账户、不直接写 auth.users、不重放迁移。运行时无服务端 key 或未确认原生注册关闭则以安全的准备中状态拒绝注册，不能把半成品说成邀请制已完成。
5. 前端增加简洁登录/注册切换：用户名、密码、邀请码（masked）字段；邀请码仅提示“输入邀请码”，不显示示例/说明/实际值，也不在 JS 比较预期邀请码。注册错误不透露邀请码/账号存在等细节；无邮箱/验证码/免登录/访客入口，旧本机数据保留但不自动合并。
6. 15001 静态文件仅允许构建清单和指定公共资源，拒绝 .env/源码/脚本/目录遍历；API 禁缓存、无通用数据库或 Admin 代理端点。外部域名与 loopback/LAN 本机开发 origin 明确列出。cloudflared 上游保持用户当前配置；不绑定全网、不泄露其它隧道配置。
